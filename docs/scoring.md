# Scoring

Per-task pass/fail is **binary**. The verifier runs `tests/test_state.py`
against `/app/answer.json`; if any assertion fails, the task scores 0.
There is no partial credit and no weighted rubric — Harbor records a
single `reward.txt` ∈ {0, 1}.

## What the verifier asserts

`tests/test_state.py` is generated by the exporter and is identical
across all 60 tasks. The twelve assertions, in order:

1. `test_answer_is_valid_json` — `/app/answer.json` exists and parses.
2. `test_answer_schema_matches_spec` — required top-level keys are
   present with the right types (`schema_version`, `is_incident`,
   `evidence`, `anomaly_keys`, `root_cause_type`, `recommended_action`).
3. `test_is_incident_true` — every committed task is an incident;
   answers that classify `is_incident = false` fail. (`nop`'s
   empty/false answer fails here.)
4. `test_evidence_files_exist` — each `evidence[i].file` is a real
   `/app/*.log` file.
5. `test_no_hallucinated_files` — `evidence[i].file` is in the
   `files` list `expected.json` records (matches exactly what the
   exporter wrote).
6. `test_evidence_lines_in_range` — each `evidence[i].line` is a valid
   1-based index in that file.
7. `test_evidence_snippets_match_log_text` — each `evidence[i].snippet`
   appears verbatim on the cited line. Anti-hallucination.
8. `test_no_cross_file_line_confusion` — every cited `(file, line)` is
   in the ground-truth set. Catches the specific failure mode of
   citing line N of file A when the anomaly is at line N of file B.
9. `test_minimum_evidence_count` — `len(evidence) >= min_evidence_count`
   (3, or `len(anomaly_locations)` if smaller). Prevents
   one-citation-and-done.
10. `test_root_cause_in_allowed_set` — `root_cause_type` is in the
    dataset's `allowed_root_causes`.
11. `test_root_cause_matches_ground_truth` — most discriminating check:
    `root_cause_type` matches the gold label.
12. `test_recommended_action_is_safe` — `recommended_action` is in
    `{escalate, investigate, no_action, open_incident, page_owner}`.
    Prevents the agent from inventing dangerous actions.

A 13th test, `test_evidence_within_ground_truth`, is a softer
subset-match version of #8. PLAN.md M3.5 originally specified exact
set-match between `evidence` and ground-truth locations, but BGL /
Thunderbird slices carry thousands of anomalies per case (the corpus
is ~1.5% non-`-`), and a realistic SRE response cites a representative
subset, not every one. The current rule: every cited evidence
location must be in the ground-truth set; the agent does not have to
cite all of it.

## Why this design

- **Binary reward** because Harbor's task contract is binary. A weighted
  per-criterion score is what `rubrics/task-implementation.toml` is for
  — that runs separately via the rubric grader and lives in
  [`docs/rubric-pass-report.md`](rubric-pass-report.md), not in the
  per-task reward.
- **Exact root-cause match** rather than fuzzy because the taxonomy is
  finite and dataset-specific (5–11 labels per dataset). A correct
  diagnosis means picking the right label.
- **Snippet match** as a verbatim string check (`snippet in line`)
  rather than equality, because real log lines can be long; trimming a
  300-char prefix is normal and still proves the agent read the actual
  file.
- **Safe-action enumeration** because the benchmark is offline-only and
  doesn't have a sandboxed prod system to verify destructive actions
  against. The closed-set check is a cheap proxy for "agent didn't
  invent `rm -rf /` or `kubectl drain`."

## Ground truth

Ground truth lives in `tasks/<slug>/tests/expected.json`. The exporter
writes it; the M6 anti-leak check (`ci_checks/check-oracle-leak.sh`)
makes sure no leaf string from `expected.json` ends up in
`environment/`. The agent never sees `tests/`; only the verifier mounts
it during the verifier phase.

The oracle agent (`solution/solve.sh`) gets a different side channel —
`solution/oracle_hints.json` — that lists the same `(file, line)`
coordinates but omits the `allowed_root_causes` list and the
`safe_recommendations` enumeration. The oracle then reads each cited
file, quotes the actual line verbatim, and emits an answer derived
from real log content. This is the M3 CLAUDE.md "Oracle solution rule"
in action — `solve.sh` cannot just `cat /tests/expected.json` because
`/tests/` isn't mounted during the agent phase.

## Aggregate scoring

When run across the full 60 tasks, the natural aggregates are:

- **pass@1** — fraction of tasks where the agent's single attempt
  yields `reward=1`.
- **pass@k** — Harbor reports this natively when `-k k` is passed.
- **per-dataset pass rate** — useful for spotting dataset-specific
  failure modes (e.g. an agent that handles HDFS but drowns on
  Thunderbird's 99.6% VAPI skew).
- **per-root-cause pass rate** — sometimes more useful than per-dataset,
  because incident families generalize across datasets (e.g. a
  network-failure pattern looks similar in BGL and Thunderbird).

`tools/leaderboard/` (M11) will turn Harbor's per-job result.json
into these aggregates. Until then, `harbor view <jobs-dir>` is the
manual path.
