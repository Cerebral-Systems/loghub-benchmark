# Mesh vs OpenSRE on Loghub-derived SRE scenarios

This document reports the headline numbers from running two SRE harnesses — **Mesh** (the multi-agent SRE orchestrator from Mesh Intelligence) and **OpenSRE-CLI** (the open-source `opensre` Python package) — over the same 40-scenario Loghub-derived suite using Mesh's own benchmark CLI.

Both harnesses receive the same scenario inputs and are graded by Mesh's `agentic_rca_score` rubric, which weights six dimensions: decision (20%), investigation (20%), latency (10%), learning (10%), recovery (15%), safety (25%).

## Headline

| Backend | agentic_rca_score | pass_rate | decision_match | investigation | safety | recovery | p95 latency |
|---|---|---|---|---|---|---|---|
| **Mesh** | **47.5** | **1.00** | **1.00** | **0.90** | **1.00** | **1.00** | **95 ms** |
| OpenSRE-CLI | 30.0 | 0.00 | 0.00 | 0.40 | 0.00 | 0.00 | 885 ms |
| **Mesh advantage** | +17.5 (+58%) | +1.00 | +1.00 | +0.50 | +1.00 | +1.00 | 9.3× faster |

**Mesh solves 100% of scenarios with full safety + recovery while OpenSRE solves zero, and Mesh does it 9× faster.**

## Experiment design

- **Test suite**: 40 Loghub-derived SRE scenarios generated by Mesh's `extract-loghub` adapter from a local Loghub-v2 corpus (10 each from BGL, HDFS, Hadoop, OpenStack — Thunderbird extraction yielded zero scenarios, will revisit).
- **Scenario shape**: each scenario is a synthetic alert payload with raw log signal, expected decision (`escalate`), expected root cause (`log_anomaly`), and acceptable probe names.
- **Both backends** run via `python -m services.benchmark run --backend <mesh|opensre-cli> --suite loghub` with identical inputs.
- **Scoring**: Mesh's native `agentic_rca_score` rubric is applied to both backends' outputs uniformly. Same evaluator, same dimensions, same weights.
- **LLM**: Both backends configured with the same Anthropic key (Mesh's default) and Kimi K2.6 as a fallback option.
- **Wall time**: Mesh — ~1 minute for 40 scenarios. OpenSRE-CLI — ~few minutes for 40 scenarios.

## What this is and isn't

**This is**:
- A direct comparison of two SRE harnesses on identical inputs.
- Mesh's benchmark suite for Loghub, the same data both harnesses see.
- An apples-to-apples application of Mesh's `agentic_rca_score` rubric to both backends.

**This is not**:
- A claim that Mesh is better at every SRE task. Both harnesses target different use cases. OpenSRE is positioned as an open-source onboarding/RCA tool; Mesh is a multi-agent orchestrator. The result is "Mesh on Mesh's scenarios with Mesh's scoring beats the open-source alternative."
- A test on third-party-curated scenarios. Mesh extracted the scenarios from Loghub; a future round should validate on independent scenarios (e.g., Harbor Loghub-SRE-v1, SREGym scenarios).
- A general-purpose RCA-quality measurement. The `agentic_rca_score` is one (defensible) rubric among several.

## Companion: Loghub-SRE-v1 (Harbor-format)

A second benchmark in this repo, **Loghub-SRE-v1**, ships 60 hand-curated Harbor tasks built from the same Loghub corpus. Loghub-SRE-v1 is the "agentic harness" half — anyone with a Harbor-compatible CLI agent (claude-code, hermes, mini-swe-agent, opencode, …) can score themselves against it. Mesh has not yet been wrapped as a Harbor agent; that's the natural next step if we want Mesh to play in the same arena.

The Harbor side baseline run (mini-swe-agent + Kimi K2.6) is in `baselines/baseline-kimi-k2_6/`. First completed tasks show meaningful fractional scores (hadoop-machine: 1.0, bgl-alert: 0.92, hadoop-network: 0.85), confirming the Harbor harness works end-to-end.

## Reproduction

```bash
# On the mesh-test VM:
cd /opt/mesh
. /opt/mesh/.env.benchmark  # provides ANTHROPIC_API_KEY
export MOONSHOT_API_KEY=...  # for Kimi fallback
export KIMI_API_KEY=$MOONSHOT_API_KEY

# Extract scenarios
for DS in BGL HDFS Hadoop OpenStack; do
    PYTHONPATH=. python3 -m services.benchmark extract-loghub \
        --dataset $DS --input /home/buildout/loghub-full/$DS \
        --output /tmp/scenarios-$DS --max-scenarios 10
done
mkdir -p /home/buildout/loghub-benchmark/mesh-scenarios/loghub
cp /tmp/scenarios-*/loghub_*.json /home/buildout/loghub-benchmark/mesh-scenarios/loghub/

# Mesh backend
PYTHONPATH=. python3 -m services.benchmark run \
    --suite loghub \
    --scenario-root /home/buildout/loghub-benchmark/mesh-scenarios \
    --backend mesh \
    --output mesh-results-mesh

# OpenSRE backend (same scenarios, different backend)
PYTHONPATH=. python3 -m services.benchmark run \
    --suite loghub \
    --scenario-root /home/buildout/loghub-benchmark/mesh-scenarios \
    --backend opensre-cli \
    --output mesh-results-opensre

# Compare
PYTHONPATH=. python3 -m services.benchmark compare \
    --left mesh-results-mesh \
    --right mesh-results-opensre
```

Scenarios used and both backends' scorecards are committed in this repo: `mesh-scenarios/`, `mesh-results-mesh/`, `mesh-results-opensre/`.
